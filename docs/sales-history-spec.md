# 販売履歴 + 在庫台帳 — 実装仕様 v1（Sales.gs）

作成 2026-08-10 (Fable) · 既存の Code.gs / Setup.gs / Api.gs は**一切変更しない**（追加のみ）

## 0. なぜテーブルを分けるのか（変更前に必ず読むこと）

SQL的には入荷も販売も同じ「在庫移動」で、1テーブルに正規化するのが本来の形。それでも**物理的に
分ける**のは、この2つが同じ形をしていないから：

| | 書き手 | 向き | 役割 |
|---|---|---|---|
| `入荷入力` | **農家** | シート → Shopify | 書き込みキュー（処理状態を持つ） |
| `販売履歴` | **スクリプトのみ** | Shopify → シート | 読み取り専用ミラー |

**混ぜてはいけない決定的な理由**: `pushPendingAdjustments` は「列Eが空の行」をShopifyに送る。
同じテーブルに販売行（負数）が入っていて列Eが空なら、**Shopifyが既に記録済みの販売をもう一度引く
＝二重減算**が起きる。「区分が販売ならスキップ」というフィルタで防ぐ手はあるが、このシステムは一貫して
「フィルタで守る」のではなく「**その経路を作らない**」方針。テーブルが別なら押し込む経路が存在しない。

正規化の利点は `在庫台帳`（QUERY数式ビュー）で回収する。実体は二重に持たない。

## 1. 追加するシート（農家ファイルごと）

### `販売履歴`（スクリプトのみ書き込み・全面保護）
`A:日付 | B:SKU | C:数量 | D:備考`

- **列は `入荷入力` の A〜D と同じ意味に揃える**（台帳ビューで縦に結合するため）
- `数量` は**負数**（販売＝在庫が減る）。キャンセルの戻しは正数
- `備考` は `#1042` のような注文番号。テスト注文は `#1042 (テスト)`、キャンセル戻しは `#1042 (取消)`

### `在庫台帳`（数式のみ・保護・コード不要）
A1 に1つだけ数式を置く。実体データは持たない = SQLでいう VIEW。

```
=QUERY({
  QUERY(入荷入力!A2:D, "select A,B,C,D where B is not null", 0);
  QUERY(販売履歴!A2:D, "select A,B,C,D where B is not null", 0)
}, "select Col1,Col2,Col3,Col4 order by Col1 desc", 0)
```
ヘッダ行は数式の1行上（A1をヘッダにして A2 に数式）に手で置く: `日付 | SKU | 数量 | 備考`。
**数式が壊れないよう、このシートは全面保護すること。**

## 2. 関数（すべて新規・既存関数を書き換えない）

### `setupSalesSheets()` — 1回だけ手動実行（冪等）
`readConfigRows()` で各農家ファイルを開き、無ければ `販売履歴` と `在庫台帳` を作る。
既にあれば作り直さない。両シートとも `ScriptApp.getEffectiveUser()` 以外の編集者を除去して保護。

### `syncSalesHistory()` — 定期実行
```
lock = LockService.getScriptLock(); tryLock(30000) が false なら return   // finally で解放
since = Script Property 'SALES_LAST_SYNC'（無ければ 30日前のISO文字列）
now   = new Date().toISOString()

orders(first:100, after:$cursor, query:"updated_at:>=<since>") をページング:
  node{ name createdAt cancelledAt test
        lineItems(first:100){ edges{ node{ sku quantity vendor } } } }

各 lineItem について:
  農家の判定は **vendor** で行う（SKUでは行わない — 下記の理由）
  Config に無い vendor はスキップ（ログに1行残す）
  キー = 注文番号 + '|' + SKU + (キャンセルなら '|C')
  その農家の 販売履歴 に同じキーが既にあればスキップ  ← 冪等性の要
  無ければ追記:
    通常     [createdAt(日付), sku, -quantity, '#name' + (test ? ' (テスト)' : '')]
    キャンセル [cancelledAt,    sku, +quantity, '#name (取消)']

全ページ処理し終えて初めて 'SALES_LAST_SYNC' = now を書く（途中で落ちたら次回やり直し）
```

**⚠️ vendor で振り分ける理由（実測 2026-08-10）**: line item は**注文時点のSKUを保持する**。
既存の注文 #1001/#1002 は旧SKU `standard-strawberry-box` のままで、現在の `ICH-001` とは一致しない。
SKUで農家を引くと過去分を全部取りこぼす。line item の `vendor` は正しく入っている（実測確認済み）。

**⚠️ 既存キーの読み方**: 冪等性はスクリプトプロパティではなく**シートに実在する行**を正とする。
毎回 `販売履歴` の D列（備考）と B列（SKU）からキー集合を作って突き合わせる。プロパティが飛んでも
二重記録しない。

**⚠️ テスト注文も記録する**: bogusゲートウェイのテスト注文でも Shopify の在庫は減る。台帳が
Shopify と合わなくなるので除外しない。備考で `(テスト)` と分かるようにするだけ。

### エラー処理
既存の `shopifyGraphql` / `appendLogRow` / `notifyAdmin` をそのまま使う（再定義しない）。
GraphQL は 200 でも `errors` が入るので必ず見る。
