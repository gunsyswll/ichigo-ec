# 健全性チェック（鮮度監視）— 実装仕様 v1

作成 2026-08-10 (Fable) · 既存ファイルは変更しない・追加のみ

## 0. なぜ作るのか（削るときはここを読む）

既存の `notifyAdmin` は**例外が起きたときしか鳴らない**。このシステムで実際に起きた障害は例外では
なかった:

> 2026-08-09、`syncProductsFromShopify` は「実行完了・エラーなし」と表示しながら**一度も走って
> いなかった**。Products シートは空のままで、実行履歴を見るまで誰も気づけなかった。

同じ形が本番で起きると、農家が入荷を入力し続けているのに在庫が動かない状態が何日も続く。
**監視すべきはスケジューラの生死ではなく、成果物の鮮度**。

## 1. 判定項目（すべて読み取りのみ。Shopifyには一切書かない）

| # | 指標 | 取得元 | 異常条件 |
|---|---|---|---|
| H1 | 在庫同期の鮮度 | マスター `Products` の `最終同期` 列の最大値 | now との差 > **60分** |
| H2 | 販売同期の鮮度 | Script Property `SALES_LAST_SYNC` | now との差 > **6時間** |
| H3 | **未処理の滞留** | 各農家 `入荷入力` の列Eが空の行 | 1件以上あり、かつ最古のA列日付が **60分**より前 |
| H4 | 送信途中で止まった行 | 列Eが `SENDING ` / `STUCK ` で始まる行 | **1件以上** |
| H5 | エラー行 | 列Eが `ERR ` で始まる行 | **1件以上**（警告扱い） |
| H6 | 直近24hの処理件数 | マスター `Log` の日時列 | 情報のみ（異常判定しない） |

H3が本命。「入力されたのに反映されていない」を直接見る指標で、H1が正常でもこれだけ異常になる
ことがある（例: ロック競合で毎回何もせず終了しているケース）。

## 2. 出力

### マスターに `Health` シート（無ければ作る・保護する）
`A:日時 | B:判定 | C:在庫同期 | D:販売同期 | E:未処理 | F:停止中 | G:エラー | H:24h処理数 | I:詳細`
- 毎回1行追記。`判定` は `OK` / `WARN` / `ALERT`
- **A1の1行上に、最新判定だけを大きく置くのではなく**、シート先頭を固定行にして最新が上に来るよう
  **降順で追記**（人が開いて最初の行を見れば分かる状態にする）

### メール（`ADMIN_EMAIL` 宛）
- **ALERT/WARN のときだけ送る。** ただし同じ状態の連投を防ぐため **6時間に1通まで**
  （`HEALTH_LAST_MAIL` プロパティ。`notifyAdmin` の1時間キーとは**別キー**にすること）
- **毎週月曜の実行では、正常でも「今週は正常です」サマリを1通送る**
  （`HEALTH_LAST_WEEKLY` プロパティで週1回に制限）
  ⚠️ これは必須。異常時のみ通知だと、**監視自体が止まったときに沈黙と正常が区別できない**。
  週1通の生存信号があれば「先週から来ていない」で気づける。

## 3. 関数
- `dailyHealthCheck()` — 上記すべてを実行。3時間おきのトリガーから呼ぶ。
- `menuHealthCheck()` — メニューから呼ぶ用。`dailyHealthCheck()` を実行して結果を `toast` で表示。

## 4. 制約
- 既存関数を再定義しない: `readConfigRows` `getConfigRows` `appendLogRow` `notifyAdmin`
  `shopifyGraphql` `onOpen` `doPost` `menuPush` `menuSync` `showFarmerFileUrls`
- 0行の範囲読み（`getRange(..., 0, ...)`）は例外になる。ヘッダしかないシートで必ず守ること。
- Shopify API を呼ばない（鮮度はシートとプロパティだけで判定できる。API障害時でも監視は動くべき）。
- 日付セルは Date と文字列が混在しうる。比較前に `new Date(v)` で正規化し、無効値はスキップ。

## 5. トリガー
`dailyHealthCheck` を **3時間おき**（時間主導型・時間ベースのタイマー）。
日次より速く気づけて、実行時間は1日あたり数十秒しか増えない。

## 6. 受け入れテスト
| # | 手順 | 期待 |
|---|---|---|
| H-T1 | そのまま実行 | `Health` シートができ、1行目に `OK`（現状は同期が新鮮） |
| H-T2 | 農家の `入荷入力` に日付を1時間以上前にした未処理行を1件置いて実行 | `ALERT`、H3が指摘され、メールが1通 |
| H-T3 | 続けてもう一度実行 | `Health` に行は増えるが**メールは増えない**（6時間制限） |
| H-T4 | その行を処理させてから実行 | `OK` に戻る |
